# Phase 3A: local in-book search

Status: proposed contract; independent review required before implementation.
Tracking: Reader issue31; Fleet221. Inspected main43558c4af2fe57dfa7b80cbb31c0c4aab0c2abba.

## Outcome and increment boundary

A reader can find a literal phrase in the currently open book and move directly to its occurrence, in scroll or paged mode. Search works for imported text and existing audio/sync documents. It runs entirely on device, changes no document fields, and never starts playback. This is the first of issue31's explicitly separate search and annotation increments. Bookmarks, highlights/notes, more accurate progress and time-left remain unimplemented Phase3 work; delivering search must not close issue31 or mark the phase complete.

Keep one dependency-free index.html, existing inert DOM helpers, import admission and local library contracts. No new storage schema, search database, worker asset, service worker, package manager, model, network call, book upload or server. Search state is transient and belongs to the currently admitted document. A query or result must never enter localStorage, IndexedDB, position synchronization, URLs, diagnostics, analytics or exports. Existing saved reading positions remain subject to their current explicit synchronization setting; search introduces no new outbound channel.

## Visible interaction

Add a labeled Search button to the existing reader controls. Disable it when no document is admitted. Opening a search sheet focuses a labeled text input and preserves the reading position and playback state. Provide Search, a status region, a list of hit buttons, Load more when required, and Close. Enter submits; Escape closes and returns focus to Search. Use the existing sheet/scrim lifecycle, keyboard containment and focus conventions; if those conventions lack containment, implement it for this sheet rather than making the background reader keyboard-active. All functions remain available without pointer input.

Typing alone does not scan. Submitting an empty or whitespace-only query clears results and reports a prompt to enter text, without navigating. Search starts from the beginning of the current document. During a scan show Searching; keep Close responsive. Submitting another query cancels the prior scan and clears its displayed results before labeling the new search. A failed replacement never presents old hits as results of the new query. Closing cancels the active scan, discards its unpublished batch and retains only already published results and their resumable cursor for that same query/document; reopening offers Load more or Search again, never implies a canceled scan completed. Each hit button names the chapter when present, the segment ordinal, and a short original-text excerpt with its matching text visually distinguished using inert text nodes. Never put imported text in HTML strings, attributes interpreted as markup, selectors, a regular expression or an executable handler.

Selecting a hit closes the sheet and moves to that occurrence. Query results remain available when reopening the sheet for the same document, including after a font/theme/reading-mode change. Closing without choosing a hit does not change position, follow state, audio time or playback. Loading another admitted document clears query and results. Merely failing an import retains the old document and its still-valid search state.

## Exact matching and locations

Search is a literal substring search over segments[].text in document order, never chapter labels, filenames, metadata or rendered HTML. No regular-expression, fuzzy, stemming, accent-removal or cross-segment match. Trim leading/trailing ECMAScript whitespace (the exact character set recognized by JavaScript trim() and /\s/u) from the submitted query, then collapse every maximal ECMAScript whitespace (the exact character set recognized by JavaScript trim() and /\s/u) run to one ordinary space in both query and searchable text. Punctuation remains significant. Treat matching as Unicode per-code-point default lowercase using JavaScript toLowerCase on each code point, independent of locale. This is a declared search transform, not a linguistic casefold: German sharp-s is not ss, accented letters remain accented, and Greek final sigma is not normalized to ordinary sigma. Do not claim locale-specific matching.

The transform must map each produced UTF-16 code unit back to the complete original code point or whitespace run that produced it. Expansion, supplementary characters, and whitespace collapsing must not shift a hit's source offsets. Each hit stores the original segment index and half-open original UTF-16 range [start,end), plus a document-generation token. Only occurrences whose transformed start/end are boundaries between complete transformed source spans are eligible; never match one unit inside a lowercase expansion or one surrogate half. Advance by the complete transformed query length for non-overlapping occurrences. Repeated matches within one segment are separate hits, ordered by source start. Example: query ana finds one non-overlapping hit in banana; query a finds three.

No normalization of the underlying document, new segment IDs, or persistence of transformed prose. Query length after trimming is limited to256 Unicode code points. Refuse a longer query with a clear inline message and no scan; do not silently truncate. Search excerpts contain at most120 Unicode code points, centered as far as possible on the hit and clipped at source-code-point boundaries. When a match exceeds the excerpt width, show its beginning and an ellipsis; navigation still uses its complete original range. Missing chapters get a plain segment label rather than an invented chapter. Exact chapter association uses admitted chapter.seg where present; for existing audio chapters without seg, use the last chapter whose admitted start is at or before the segment start, following current chapter-time navigation. Never guess from chapter prose.

## Complete results without locking the reader

Display at most50 hits per batch. Scan sequentially until finding the51st hit or reaching the end; retain only the displayed hits, one pending hit and a cursor. When more exist, state At least51 matches; Load more continues from the pending hit and cursor, retaining previous displayed hits. Never claim a complete count from a truncated scan. After reaching the end report the exact total. Cap retained displayed hits at500; if additional hits exist report First500 matches; refine your search and remove Load more. The cap is visible and does not redefine the matcher or produce a fake complete count.

Process text in bounded slices, yielding to the browser between slices, including within one enormous segment. A slice may transform/scan at most16,384 original UTF-16 code units, ending on a code-point boundary; preserve a bounded overlap sufficient for the transformed query and its source mapping so matches across slices are found exactly once. Do not build a transformed copy of the entire book or precompute all hit records. Check the active scan/query and admitted-document generation at every continuation and immediately before publishing results or navigating. Generation state is in-memory ordinary counters, not content hashes or custody machinery. A canceled, replaced or stale scan must not publish a partial old list or navigate the new book.

An internal scan or pre-effect validation failure reports a plain generic error, leaves the document and current reading place intact, discards the failed scan's unpublished results and allows retry. A post-audio-transition geometry failure follows the paused/no-unverified-position-save rule below; do not promise unchanged playback after that transition. Never include query/prose in the error. Already published current-generation results remain valid. File import, book switching and library deletion preserve their existing cancellation and ownership rules; do not modify them to support search.

## Navigation and persistence

Do not route audio hits through seekTo: its existing behavior starts paused audio. The search navigation path validates the generation, segment and range before any effect, then pauses any currently playing audio and moves the reader to the original hit range. For an audio document, update its current reading segment and chapter using the existing paused-reading semantics; update audio.currentTime to the segment's admitted start only when there is a playable current audio source with finite duration and the target is within it. Never invent a word timestamp from a character position. Later explicit Play uses the existing read-to-listen handoff. Existing pause and seeked handlers reset readingSeg and may call setSeg after the selection. The completed search navigation must retain its selected segment and character anchor after those asynchronous events settle. Use a small transient navigation-generation/ownership guard in the existing event path; cancel that ownership on another user audio command, a new selection or a document change. Do not replay old navigation after cancellation, depend on an arbitrary timer, or suppress normal pause/seek behavior outside the search-owned transition. Validate source range and document ownership before effects, and resolve geometry against source-faithful paused rendering before final position/save; publication of a successful navigation occurs only after those checks. If a late failure occurs after an audio transition, leave playback paused, report the failure and do not persist an unverified target. With no playable audio, search still navigates the text and cannot trigger loading or playback.

For text mode use the existing reading position and saved-place path. Reveal the hit's original character range, rather than merely the first page of its segment: a long segment can span several columns. Reuse the current character-anchor/Range geometry and pager where appropriate, keeping imported prose inert and leaving build() and the shared document schema unchanged. In scroll mode reveal the matching range; in paged mode reveal its containing column. Do not add match-highlight wrappers or rewrite the document to highlight hits, which could disturb word timing, segment IDs or anchor mapping. The result excerpt provides match emphasis; the reader keeps its existing segment highlight. In audio mode, setSeg currently renders words[].w plus spaces; that can differ from segments[].text even for an admitted document. Original offsets must never index this different rendered string. While a search-selected segment is paused, render its admitted segments[].text as inert text using the existing plain-segment representation, preserve its segment highlight, and resolve hit geometry against that exact source string. Keep word timing data unchanged. Explicit subsequent playback restores the ordinary timed-word rendering and glow; other segments and ordinary non-search playback retain their existing behavior. No parallel reader, fuzzy offset mapping or replacement source is permitted. Re-resolve geometry from the current layout at selection, so font, measure, orientation and mode changes cannot leave a stale pixel/page target.

Before any effect, confirm the hit still exists, its source range is valid and its document generation is current; refusal at this stage leaves position and playback unchanged. Before committing reading position changes or saving, confirm geometry resolves in the source-faithful rendering. If it does not, report Unable to show this match and do not commit or save a new reading position. A required audio pause or seek may already have occurred; keep playback paused and report that failure rather than claiming the transition was atomic. Persist through the current saved-place APIs only after successful navigation, preserving unsaved-document and storage-failure behavior. No new identity or position record. Existing segment-level persistence can restore the segment rather than the exact searched character after reload; do not advertise exact-character resume or time-left from this feature.

## Acceptance evidence for implementation

Use invented prose only. Behavioral tests must cover the visible path, not source-text hashes or internal helper inventories:

1. Literal substring, case, punctuation, whitespace collapsing, non-overlap and separate repeated occurrences; no cross-segment matching. Include supplementary characters, lowercase expansion boundaries, combining accents, U+0085 (not collapsed by ECMAScript whitespace), U+FEFF (collapsed/trimmed), and original UTF-16 offsets. Query length and excerpt bounds do not split a code point.
2. Stable segment/source ordering, missing and existing chapter labels, first50/51st pending hit, successive batches, exact count only at end, visible500 cap and refinement, no duplicates or dropped boundary matches.
3. One enormous segment and a multi-segment book yield during a scan; an input/Close event and a replacement-query or document-generation change cancel stale publication. Test the limit by behavior rather than relying on elapsed-time benchmarks alone.
4. Inert markup-like query/prose, no HTML interpretation or executable content, no query/results in storage/sync/URL/network/logs. Exercise the actual sheet with keyboard, input label, status announcements, focus return and no-match/error states.
5. Scroll and paged hit selection reaches a later occurrence in a multi-column segment. Reflow between search and selection resolves fresh geometry. A stale or invalid range refuses before any audio or position effect.
6. Text hit selection saves through the existing book position route; unsaved books remain readable, and storage failure follows the existing warning policy. Closing or a failed scan/import preserves the old reading position.
7. Audio selection from playing and paused states ends paused; no play call, no seekTo autoplay, correct chapter/reading segment and admitted segment time when playable, including after real pause/seeked events settle. Include an admitted document whose timed-word text differs from segments[].text and prove the hit uses source-faithful paused rendering, then explicit Play restores timed-word rendering. No audio source and out-of-duration targets remain text-navigable without an invalid seek. Explicit subsequent Play retains the existing handoff behavior.
8. Book replacement and library reopen clear search state; failed import does not. A scan and old result racing with a newer book cannot publish, navigate or save that book's position.

Run the full dependency-free local gate from AGENTS/check.sh through the supported native gate runner; exercise real browser layout in both modes for geometry and keyboard behavior. Node/pure matcher tests cannot prove DOM Range geometry, focus or audio interaction. Obtain independent exact-head build review and preserve normal Claude/integration-train clearance. Draft delivery is code preparation, never merge or Pages deployment authorization. Review any contract ambiguity before build, keeping unrelated Phase3 work visible rather than claiming search completes the roadmap.
